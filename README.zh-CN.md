# chat-to-code-session

把 claude.ai 上的一段对话原样接到 Claude Code 里继续聊,一个字不改。

[English](README.md)

## 它做什么

Claude Code 把每个会话存成一个文件:`~/.claude/projects/<目录名>/<会话 id>.jsonl`,一行一条消息。
`claude --resume <会话 id>` 做的事只是把这个文件读出来,交给模型当作"我们聊到这儿了"。它不核对文件从哪来。

`chat2code.py` 用你自己的聊天记录写出这样一个文件:

- 第一条放在 Code 自己放"接续上一段对话"头部的位置,写明这些消息是导入的、从哪导的、多少条,还可以带上你自己写的说明(比如一段日记、谁是谁);
- 后面是原话,按原顺序、原时间戳,一问一答交替。

打开这个会话,模型面前就是整段对话的原文。不做任何概括,除非你自己写。不往任何地方发数据,只在你硬盘上写一个文件。

2026 年 9 月,一段在 claude.ai 上聊了三个月的对话就是这么搬进 Claude Code 的,至今还在那边继续。办法很简单;放出来是因为换工具就丢掉一段长对话,这种难受很常见,也本来可以不发生。

## 安装

Python 3.9 以上,不用装别的。把 `chat2code.py` 复制到任何地方。

## 拿到导出文件

claude.ai → 设置 → 隐私 → **导出数据**。会收到一个 zip,里面有 `conversations.json`,包含你全部对话;脚本让你挑一段。

记录在别处的话,写成一份简单的 Markdown(见 `samples/transcript.sample.md`):一行 `**User:**` 或 `**Assistant:**`(也认 `Human:`/`Claude:`,带不带 `#`、`**` 都行),下面是正文;要时间戳就在那一行末尾加 `@ 2026-04-01T09:00:00Z`。

## 用法

```bash
# 看导出文件里有哪些对话
python chat2code.py --input conversations.json --list

# 把其中一段导进你要工作的项目目录
python chat2code.py --input conversations.json --conversation "Garden planning" --cwd /path/to/project

# 然后在那个目录里:
cd /path/to/project
claude --resume <上面打印出来的会话 id>
```

要紧的几个参数:

| 参数 | 意思 |
|---|---|
| `--cwd DIR` | 会话归属的项目目录(默认当前目录)。之后要在同一目录里 resume。 |
| `--summary FILE` | 你自己写的说明(日记、人物、定下的事),原样放进头部那条 |
| `--max-chars N` | 只保留最近的消息,直到 N 个字符(默认 240000);更早的留在导出文件里 |
| `--all` | 全部导入。只适合 1M 上下文的模型;200k 的会立刻触发压缩 |
| `--model ID` | 写在导入的助手消息上的模型名(默认 `claude-opus-4-6`) |
| `--out FILE` | 写到你指定的路径而不是 projects 文件夹(试跑用) |
| `--list` | 列出导出文件里的对话然后退出 |

脚本不覆盖已有文件,不碰你别的会话。

## 该有什么预期(实话)

- **模型读到的是自己当时说的话,不是概括。** 这就是全部要点。它会把导入的消息当成"我们聊到这儿了",因为 Claude Code 对任何 resume 的会话都是这么交给它的。
- **头部那条写明了是导入的。** 不对模型隐瞒来处。你给的 `--summary` 会标明是你提供的说明。
- **思考块不会复现。** 导出里只有可见文字,助手消息重建成纯文本。
- **太长会从前面裁。** 默认保留最近约 24 万字符,头部会写明去掉了多少条更早的。
- **同一方连发的消息会合并**(中间空一行),因为接口要求严格交替。字不改。
- **JSONL 的字段是 Claude Code 的内部格式,不是公开接口。** 字段取自 Claude Code 2.1.258–2.1.295 的真实会话文件(Windows,桌面版与 CLI),用 CLI 测过。以后版本可能改;要是 `--resume` 不认生成的文件了,开 issue 时带上你的 `claude --version`。
- **模型名只是写上去的,没有核对。** 在意的话用 `--model` 指定。

## 为什么行

模型自己没有记忆。壳子交给它的"对话"就是它的全部上下文。Claude Code 交给它的是那个 JSONL 文件。所以这个脚本写出来的会话和在 Code 里真聊出来的会话,从里面看一模一样——前提是里面的话确实是当时说的话。别改它们;导入的价值就在没有一句是转述。

## 隐私

脚本读一个文件、写一个文件,都在你机器上。仓库的 `.gitignore` 排除了 `conversations.json` 和所有 `*.jsonl`,导出文件不会被误提交。样例是编的。
